# Game Update Intelligence (GUI) — v3.0 (Phase 1 + 업데이트 중심 화면 개편)

업데이트 공지와 Sensor Tower **추정** 매출·DAU를 연결해, **업데이트 1건마다 어떤 크기·모양의 반응이 있었는지, 그 결론이 비교 기준에 얼마나 민감한지** 보여주는 Streamlit 도구입니다. 시작하면 바로 등록된 프로젝트(쿠키런: 크럼블)의 업데이트 진단 리포트가 열립니다. CSV를 올릴 필요가 없습니다.

## 실행 방법 (처음 한 번)
1. Python 3.10 이상 설치
2. 이 폴더에서 터미널(PowerShell) 열기
3. `python -m pip install -r requirements.txt`
4. `python -m streamlit run app.py`  (`streamlit` 명령이 인식되지 않는 PC에서도 동작합니다. 안 되면 `py -m streamlit run app.py`)
5. 브라우저에서 http://localhost:8501 접속

## 계산이 맞는지 확인하기 (테스트)
1. `python -m pip install -r requirements-dev.txt`
2. `python -m pytest -v`
3. 마지막 줄이 `49 passed`이면 정상입니다. MVP 2 계산값(D0 ×0.93 / ×2.08 / ×1.40 / ×3.86, 7일 변화 범위 4건) 회귀, 프로젝트 등록 검증, 분석 불가 처리, CSV 병합 규칙 등을 검사합니다.

## 화면 흐름
1. 상단: **분석 게임 → 업데이트 → 집계 범위** 선택 (집계 범위 기본값은 매출·DAU 공통 개별 국가 합산)
2. **업데이트 진단 리포트**: 요약 카드 → KPI 4개(이후 7일 추정 매출 합계 vs 이전 7일 [대표 성과], 이후 7일 일평균 DAU vs 이전 7일 [대표 성과], D0 추정 매출 vs 7일 전 같은 요일 [참고], 이후 7일 최고 일 추정 매출) → 주요 발견([관찰]) →
   ① 이후 7일 vs 이전 7일 일별 차트 ② 국가별 비교(이전·이후 7일 값, 증감액, 증감률, 합계 행) ③ 일자별 값(7일 전 같은 요일 비교, 참고) ④ 공지 사실(접기) / 해석 가설 / 함께 고려할 요인 / 한계 ⑤ 추가 분석·CSV 보완·데이터 점검
3. 왼쪽 메뉴: 업데이트 비교 · 국가별 반응 · 업데이트 구성 · AI 사업 분석 · 전체 개요
- 누적 매출·전체 일별 그래프는 메인에서 빼고 **전체 개요** 안의 참고 항목으로 옮겼습니다.
- 등록되지 않았거나 데이터가 부족한 항목은 값을 채우지 않고 **"분석 불가"**와 사유를 표시합니다.

## 파일 구성
| 파일 | 역할 |
|---|---|
| `app.py` | 진입점: 프로젝트·업데이트 선택, 데이터 불러오기, 화면 연결 |
| `registry.py` | 프로젝트 등록 폴더 읽기·검증, 등록 CSV + 업로드 병합 |
| `report.py` | 업데이트 1건 진단에 필요한 모든 계산 결과를 묶음 (화면은 이것만 그림) |
| `analysis.py` | 기본 계산·데이터 점검·진단 함수 (Streamlit 없이 테스트 가능) |
| `charts.py`, `ui.py` | Plotly 차트, 스타일·카드·표시 형식 |
| `views/` | 화면별 코드 (diagnosis, compare, country, structure, ai, overview) |
| `projects/<프로젝트>/` | `project.json`(이름·출처·범주), `revenue.csv`, `dau.csv`, `updates.json`(공지 요약·분류) |
| `tests/` | 회귀·동작 테스트 |

## 새 업데이트·새 게임 추가
- **업데이트 추가**: `projects/cookierun_crumble/updates.json`에 같은 형식으로 항목 추가 (등록된 업데이트만 분석 대상). 항목은 문자열 또는 `{"text": "...", "kind": "신규 패스"}` 형식입니다. 공지에 없는 내용은 `pending_review`에 "원문 대조 필요"로 적고 확정 사실처럼 쓰지 않습니다.
- **기간 확장·국가 추가**: 진단 화면 맨 아래 "추가 분석 및 데이터 보완 → CSV 보완 업로드". 날짜·국가는 합집합, 겹치는 값이 다르면 **등록 값을 유지**하고 충돌 건수를 표시합니다(옵션으로 업로드 값 우선). 보간하지 않으며 업로드 내용은 저장소에 저장되지 않습니다. 영구 반영하려면 `projects/` 안의 CSV를 교체하세요.
- **새 게임**: `projects/` 아래에 같은 구성의 폴더를 추가하면 프로젝트 목록에 나타납니다 (등록 UI는 아직 없음). 한 프로젝트의 오류가 다른 프로젝트를 막지 않습니다.

## 분석 규칙
- 모든 숫자는 Python이 계산하고, Gemini는 해석·서술만 합니다. 매출은 항상 "추정 매출"입니다.
- **비교 방식**: 대표 성과는 이전 7일(D-7~D-1)과 이후 7일(D0~D+6, 업데이트 당일 포함)의 같은 길이 비교이며 모든 화면에 고정 적용됩니다(D+7 이후는 집계에 넣지 않음). D0를 7일 전 같은 요일과 비교하는 값은 하루 단위 참고값이며 업데이트 효과를 직접 측정하는 지표가 아닙니다. 요일 구성이 같아도 추세·연휴·프로모션 영향은 남아 있습니다.
- **기저 진단·관측 변동성·기존 판정**: 업계에서 쓰는 지표가 아니라 메인 화면에서 제거했습니다. 코드(`analysis.py`)와 "업데이트 비교 → 기존 비교 화면(고급)" 펼침 항목에만 참고용으로 남아 있습니다.
- DAU는 '공통 7개국 합산'과 '파일 전체 합계'를 구분합니다. 매출·DAU의 집계 범위가 같은지 확인되지 않았으므로 ARPDAU 등 결합 지표는 계산하지 않습니다.
- 메이저·마이너는 공지 구성 기준의 사후 분류이며 유형별 n=2이므로 우열이나 통계적 유의성을 주장하지 않습니다.

## 이 도구의 역할
기간 중심 성과 리포트가 전체 기간의 성과를 설명한다면, 이 도구는 업데이트 1건을 같은 절차로 진단합니다. 다른 리포트의 주장을 검증·반박하지 않으며, 집계 기간·스토어 범위·통화가 달라 절대 수치를 직접 대조하지 않습니다. (비교표는 앱의 "전체 개요"에 있습니다.)

## 주의
- 공지 항목은 전달받은 원문을 요약·분류한 것이며 원문 전체가 아닙니다. 9/23 캐릭터 밸런스(능력치·버프) 변경은 요약에 없어 "원문 대조 필요"로 표시했습니다.
- Sensor Tower 수치는 추정치이며 업데이트의 인과적 매출 기여를 입증하지 않습니다. 원본 CSV의 통화·플랫폼·집계 범위는 확인되지 않았습니다.
- 업데이트는 공지 기준 13:00 전후 반영되며 Sensor Tower 일 경계(시간대)가 확정되지 않아 D0 해석에 주의가 필요합니다.
- **배포 전 확인 필요**: Sensor Tower 데이터의 외부 공개·재배포 가능 여부. 불가하면 `projects/*/revenue.csv`, `dau.csv`를 공개 저장소에 올리지 마세요.
- AI 사업 분석: Gemini 호출 시 요약 수치와 입력 텍스트가 외부로 전송됩니다. API 키 보관 방식과 SSL 검증 기본값은 Phase 3~4에서 개선 예정이며 이번 단계에서는 기존 동작을 유지했습니다 (현재 "인증서 검증 끄기"가 기본 체크 상태 — 개인 네트워크에서는 해제하세요).

## 변경 이력
- **v3.0 화면 개편**: 프로젝트 등록 구조(`projects/`), 업데이트 진단 중심 화면, 업로드 병합(보조 기능), 반응 지속성·시점 점검 추가, 공지 분류 수정(8/13 환산 예고는 신규 BM 아님, 9/23 차원의 이면은 PvE, 신규 패스·성장 장벽 완화·길드 보상 구분), 기존 화면은 각 메뉴/펼침 항목으로 보존. MVP 2와 계산 함수 전수 비교 차이 0건.
- **데이터 기간 확장**: 등록 CSV를 8/1~9/30(61일)에서 **7/30~9/30(63일)**로 교체했습니다(겹치는 8/1~9/30 610칸×2파일은 기존 값과 차이 0). 8/13의 직전 14일 구간이 처음으로 계산 가능해졌고, MVP 일별 잡음 12.3%는 8/1 이후로 자르면 그대로 재현되며 전체 63일 기준으로는 12.9%로 달라집니다(의도된 데이터 변경).
- **v4 검토 반영**: ① DAU 합계를 '공통 7개국 DAU 합계(국가별 추정치의 단순 합, 고유 이용자 수 아님)'로 표기하고 매출·DAU가 같은 7개국 열로 계산되는지 점검(`report.scope_audit`)을 추가 ② 비교 기간 슬라이더를 제거하고 이전 7일 vs 이후 7일로 고정 ③ 국가별 표에 이전·이후 7일 값, 증감액, 증감률, 합계 행 추가 ④ AI 프롬프트에 단정 금지 항목(캐릭터·BM 기여, 결제자·ARPPU, 이용자 증가, 운영 이슈 인과)과 4단 구조 적용, AI 페이지의 인증서 검증 기본값을 켬으로 변경 ⑤ 주요 발견을 KPI 바로 아래로 이동, 공지 목록 접기.
- **v3.0 Phase 1**: 계산을 `analysis.py`로 분리, 기존 판정 명칭 구분, 기저 진단·관측 변동성·데이터 점검 추가.
- **MVP 2**: 최초 버전.
